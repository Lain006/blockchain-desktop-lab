# 区块链教学桌面控制台

一个面向初学者的本机多节点区块链实验：用按钮启动节点、连接节点、挖矿和查看实际同步过程，关闭软件后可以恢复自己的实验。

每个节点运行在独立进程中，拥有自己的链文件，通过真实 TCP P2P 交换区块。桌面界面提供操作，原 Vue 网页继续只读观察。

![真实三节点桌面实验](docs/screenshots/01-desktop.png)

> 截图使用独立临时数据生成，没有包含作者的个人实验存档、桌面、账号或目录。端口与区块哈希来自该次真实运行，和你第一次启动时不同属于正常情况。

需要老师要求的“后端 CLI 操作 + 只读网页”版本，请看独立项目 [blockchain-web-observatory](https://github.com/Lain006/blockchain-web-observatory)。两个项目不要混用启动窗口和网页地址。

## 最快使用：下载 Windows 成品

1. 打开本仓库的 [Releases](https://github.com/Lain006/blockchain-desktop-lab/releases)。
2. 下载附件 **`Blockchain-Lab-1.0.0-win-x64.zip`**。不要把 GitHub 自动生成的 `Source code.zip` 当成可执行成品。
3. 右键 ZIP，选择“全部解压”。解压到你有读写权限的文件夹，中文和空格路径均已本机验证。
4. 双击文件夹里的 **`区块链教学控制台.exe`**。必须保留旁边的 `resources/`、DLL 等文件，不能只复制一个 exe。
5. 等待节点状态变为“运行中”。之后按下面的图文步骤操作即可。

成品包含 Electron/Node.js 运行环境，**日常不需要额外安装 Node.js、npm、数据库或配置 API key**。首次下载需要网络，实验本身在本机运行，不依赖云端区块链服务。

本版为 Windows x64 解压版，未进行代码签名；源码可供检查和自行构建。第二台全新 Windows、Windows ARM 或其他操作系统尚未作同等验收。

## 第一次打开会发生什么

程序创建一个新的本机实验，启动 A/B 两个独立节点，并建立连接。初始每个节点只有一个固定的创世区块，软件不会预先挖出展示数据。

| 页面位置 | 你能看到什么 | 含义 |
|---|---|---|
| 左侧节点列表 | A/B/C、运行状态、区块数 | 各自独立进程的实际状态 |
| 中间“当前操作” | 当前选择的节点 | 后面的挖矿、停止、连接操作作用于它 |
| 区块总数 | 包含创世块的数量 | 第一次为 1；最高区块 index 是数量减 1 |
| 实际连接 | 当前直接连接的其他节点 | 和“网页观测列表”不是一回事 |
| 区块内容输入框 | 你要记录的文字 | 写入区块的 Data，必须是文本 |
| 下方“发生了什么” | 真实保存、接收、启停结果 | 不会根据广播就假设其他节点已收到 |
| 技术详情 | P2P/API 端口、完整 Hash、稳定 ID、原始日志 | 用于理解和排查，不必每天手填 |

“端口”是找到运行中程序的门牌号，不是节点数据本身。软件按稳定节点 ID 保存链，所以换了空闲端口仍能加载同一个节点的数据。

## 新增区块：选择节点并挖矿

1. 在左侧点击节点 A，确认其为“运行中”。
2. 在“写入新区块的内容”里输入一小段文字，例如 `第一次区块链课程实验`。
3. 点击“挖矿生成区块”。
4. 观察教学记录：A 应出现校验并保存成功的记录；已连接的 B 独立验证后，会出现自己的接收成功记录。
5. 两边区块总数应从 1 变为 2，最新 Hash 相同。可以选择 B 再挖一个区块，等待反向同步。

挖矿（mining）会反复尝试 nonce，使哈希满足课程固定难度。本项目为三个前导零，不需要购买算力或支付费用。

教学记录可展开“等价命令与操作”：

```text
mine "第一次区块链课程实验"
```

这是对应课程 CLI 的写法。你不需要再把它手工执行一次，否则会再挖出一个区块。

软件显示真实 nonce、耗时和最终结果，不伪造挖矿百分比。区块文本受大小限制；不要把密码、私钥、身份信息或其他隐私放进 Data。

## 增加、停止和重新连接节点

### 增加 C

1. 点击右上角“新增节点”。
2. 选择“启动后连接到：节点 A”，或选择“暂不连接，独立运行”。
3. 点击“创建并启动”。程序分配空闲端口并创建 C 自己的链文件。
4. 如果连到 A，C 通过 P2P 接收有效长链，教学记录显示它实际校验和保存的结果。

新节点会自动进入桌面管理器的观测目录，不需要手填 `observe`。这项自动管理属于桌面项目，与 CLI 网页项目不同。

### 停止节点与重新启动

选择节点，点击“停止节点”。它的 API/P2P 服务会关闭，**已经保存的链文件会保留**。再次点击“启动节点”，它会读取自己的文件，重新监听端口并尝试恢复配置好的连接。

停止 A 不会停止统一的网页目录服务，仍可观察在线的 B/C。

### 连接与断开

选择一个运行中节点，在“连接到节点”下拉框选择另一个在线节点：

- 点击“连接节点”：建立实际 TCP P2P 连接，并记录下次要恢复的连接关系。
- 点击“断开连接”：关闭这两个节点之间的直接连接，并移除这条期望连接关系。

如果 A/B/C 之间还有其他路径，区块可能沿另一条路径传播；“断开 A 与 B”不一定意味着 A 与整个网络隔离。

这个版本在接收有效新区块后会继续向邻居转发，实际测试覆盖 C → A → B。收到的区块仍必须通过验证，不会仅因为另一个节点发来就盲目接受。

## 网页为什么没有变化

**从桌面控制台点击“打开只读观测站”进入网页。**不要继续看以前命令行/Vite 打开的旧标签。

![桌面管理器提供的真实只读网页](docs/screenshots/03-observation.png)

软件会为本次实验启动一个本机网页入口。端口由系统选择，例如可能是 `http://127.0.0.1:某个空闲端口/`。下次运行网页端口可以变化，节点和区块仍从保存的实验恢复。

```text
桌面管理器提供 /nodes
        ↓ 返回当前实验在线节点的 API 地址
网页读取各节点 /nodeInfo、/blocks、/peers
```

例如，浏览器里仍开着另一项目的 `5173` 或 `5175`，它可能正在刷新另一组 API，当然看不到当前桌面实验的变化。网页端口数字本身不能证明它属于哪个实验。

在正确网页里，确认自动刷新开启；普通轮询约每轮完成后 2 秒，隐藏页面暂停采样，失败时会退避。也可点击“刷新链”。新增区块时画布可能保留你正在检查的旧区块，点击“定位最新”再检查 Data。

网页保持只读，没有新增/删除节点、挖矿或任意改链按钮。所有管理动作由本地后端执行。

## 保存与恢复

关闭软件窗口会结束它管理的节点进程，下次打开会恢复上次希望运行的节点、稳定 ID、有效区块链及连接关系。单独停止的节点会保持停止状态，直到你再次启动它。

数据存放在当前 Windows 用户的应用数据目录，与解压的软件文件夹分开。**点击“数据目录”查看实际位置**，不要照抄作者电脑的路径。

```text
lab/
├─ experiment.json       节点 ID、名称、期望运行状态、连接配置
├─ experiment.json.bak   上一份有效配置备份
└─ nodes/
   ├─ <节点ID>.json      这个节点的链
   └─ <节点ID>.json.bak  上一份有效链备份
```

链在有效追加、P2P 收到有效区块或替换为更长有效链时自动保存。先写文件成功，再提交内存变更；保存失败会报告错误，不能当作“已经保存”。

启动时会重新校验存档。主文件损坏时尝试有效备份并提示，可能回到上一份有效状态；主文件和备份都无效时拒绝加载，不静默清空你的实验。

### 备份、升级和迁移

1. 先关闭软件，等待节点退出。
2. 备份完整 `lab/` 文件夹，而不是仅备份一个节点 JSON。
3. 升级时可替换解压的软件文件，保留用户数据。
4. 迁移电脑时，在目标电脑先打开软件确认实际数据目录，再关闭软件，备份目标现有数据后迁入完整 `lab/`。

GitHub 仓库和 Releases 不包含作者的 `lab/`、用户区块、个人记忆文件或凭据。你自己备份的实验文件可能含有 Data 内容，请按自己的隐私需求保管。

## 删除节点或区块是什么意思

首版没有“永久删除节点数据”按钮。需要暂时不用某节点，使用“停止节点”；文件保留以便恢复。

**没有删除任意历史区块的功能。**区块通过前块 Hash 关联，任意删改会破坏链验证；控制台不会把一个按钮伪装成合法删块。

如果需要全新实验，先关闭软件并完整备份 `lab/`，再把原 `lab/` 重命名留存，重新打开会新建 A/B。不要一边运行软件一边移动数据，不要只清空某个节点然后期望旧网络忘记更长链。恢复实验时关闭软件，再恢复完整备份。

等长分叉不会合并：断网期间两边都产生同高度的不同块时，沿用课程规则，只接受通过验证的更长链。这不是以太坊或生产级共识网络。

## 从源码运行

适合想看实现、修改代码或自行构建的人。仅使用成品可跳过本节。

### 环境

- Node.js `22.12` 及以上的 22.x 或 24.x，npm 随 Node.js 安装；本机测试使用 Node.js 22.20。
- 首次安装依赖、下载 Electron 需要网络。
- 桌面和截图验收面向 Windows x64。浏览器验收默认使用已安装的 Microsoft Edge。
- 可选 Git，用于克隆；也可下载 Source code ZIP 并解压。

在系统终端执行：

```text
git clone https://github.com/Lain006/blockchain-desktop-lab.git
cd blockchain-desktop-lab
npm install
npm start
```

`npm install` 安装根目录依赖后，会自动使用锁文件安装后端、前端子目录依赖。`npm start` 构建网页与桌面 UI，再启动 Electron。它与下载成品一样会管理独立进程。

开发者需要重装子目录依赖时，根目录执行 `npm run setup`。这不清空实验数据。

### Electron 下载失败怎么办

npm 包和 Electron 运行环境是两项下载。若网络无法访问官方发布文件，可在同一系统终端指定 Electron 镜像后重试，项目不会把代理地址写死：

PowerShell：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
npm start
```

CMD：

```cmd
set "ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/"
npm start
```

若你的环境已经配置 HTTP(S) 代理，可按 Electron 下载器支持的方式设置 `ELECTRON_GET_USE_PROXY=true`。不要把示例代理端口当作所有电脑的配置；不要将 token 或代理密码提交到仓库。

### 手动 CLI 仍然可用

```text
npm --prefix blockchaindemo start
```

这个独立 CLI 默认仅使用内存，不自动接管桌面存档。想按完整手动步骤学习，请使用网页课程项目的教程；不要把手动创建的进程误当成桌面节点。

## 项目结构与关键代码

```text
desktop/
├─ main.cjs                 Electron 窗口、单实例、受限 IPC
├─ preload.cjs              安全桥接，界面不直接读文件/执行 shell
├─ manager.cjs              节点进程、配置、期望连接、事件
├─ node-worker.cjs          每个独立节点的结构化操作入口
├─ observation-server.cjs   独立只读目录与打包网页服务
├─ renderer/                Vue 3 + TypeScript 控制台
└─ tests/                   存储/管理器和真实 Electron 验收
blockchaindemo/
├─ Block.js / Blockchain.js 区块、哈希、难度与有效链
├─ runtime.js               CLI 与桌面共用的运行操作
├─ json-store.js            校验、临时文件、备份与恢复
├─ P2p.js                   真实 TCP P2P
└─ cli.js                   课程手动命令行
frontend/                   只读区块链观测站
docs/                       架构、流程、配置、权限和验收
scripts/                    首次安装与截图重现
```

需要知道网页连哪组节点：看 `frontend/src/composables/useObservatory.ts` 的目录地址选择，以及 `desktop/observation-server.cjs` 如何注入当前目录地址、返回当前实验节点列表。

## 测试、打包与发布

在根目录执行：

```text
npm test              # 存储失败/备份恢复、真实三进程、端口冲突及退出
npm run test:backend  # 原课程后端完整测试
npm run test:web      # 网页类型检查及逻辑测试
npm run typecheck     # 桌面 Vue/TypeScript 类型检查
npm run test:e2e      # 只读网页的 Edge 场景
npm run build         # 网页和桌面 UI 构建
npm run test:desktop  # 实际 Electron 窗口按钮→后端→保存恢复
npm run docs:screenshots # 独立临时数据运行验收并生成 README 截图
npm run package       # Windows x64 ZIP，输出 delivery/
```

构建者需要先确保 Electron 下载成功。`delivery/`、依赖、缓存和临时验收数据不提交 Git；可执行 ZIP 通过 Releases 分发。

本仓库配置 GitHub Actions：提交后在 Windows runner 上运行自动检查。维护者运行 `npm run package` 构建 ZIP、检查 SHA256 后上传到对应版本的 Releases。检查成功与否以仓库 Actions 页面为准；源代码存在不等于某次远程构建已经成功。

## 问题排查与边界

| 现象 | 应怎样检查 |
|---|---|
| 桌面变了，网页没变 | 从当前客户端重新打开只读观测站，核对当前 API；不要看另一套 Vite 网页 |
| 想一直用某个端口保存数据 | 不需要；数据按稳定 ID 保存，端口冲突可换 |
| 节点异常退出 | 看教学记录和原始日志；选择该节点重新启动，其他节点不必一起重启 |
| 区块保存失败 | 按错误检查数据目录权限、可用空间等；不要把该次失败当成成功 |
| 本地链不同步 | 看实际连接、长链规则和节点错误；等待上一块同步完成再从另一端挖矿 |
| 停了 A，B/C 页面还在 | 正常，网页目录独立于 A；只显示在线节点 |
| 退出后区块没了 | 确认运行的是桌面版，不是内存 CLI；核对数据目录、恢复提示和是否使用另一个系统用户 |
| 第二次双击没有新窗口 | 正常，应激活已有单实例窗口，不重复建立实验 |
| 在 ZIP 内直接点 exe 报缺 DLL | 先完整解压整个 ZIP |
| 源码版启动找不到包 | 在仓库根目录完成 `npm install`，不要仅安装 frontend |

已在本机对源码与实际打包软件做真实三节点、按钮操作、退出释放和恢复验证；实际包在中文含空格路径、启动 PATH 不提供系统 Node.js 的隔离环境通过。**这不等同于第二台干净电脑、跨电脑 P2P、公网部署或老师人工验收。**

未提供身份认证、钱包、交易签名、真实资产、自动更新和永久删数据界面。服务默认监听本机，不能作为生产公网服务。权限与验证边界见 [架构说明](docs/ARCHITECTURE.md) 和 [验收说明](docs/TESTING.md)。字体许可见 [OFL.txt](frontend/public/fonts/OFL.txt)。
